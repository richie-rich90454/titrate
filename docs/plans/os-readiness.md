## 1. Exit contract

From `ROADMAP.md` §1 and §20:

> `trc --target x86_64-unknown-none` produces a bootable image with no compiler, Rust std, CRT, or LLVM-C in the output; a minimal kernel boots in QEMU.

That sentence is four independent requirements:

1. **Target selection works.** A `none` triple is accepted, validated, and used for code generation and linking.
2. **The image is freestanding.** No compiler, Rust `std`, C runtime, or LLVM-C code/data survives into the final binary.
3. **The image is bootable.** A defined entry point, a linker script, and a boot protocol hand control to Titrate code.
4. **A kernel runs.** The minimal image drives a serial or framebuffer console, handles interrupts, and stays alive under QEMU (gate G10).

Phase 14 is a multi-year program. This document is the design for that program; it is not a claim that any of the four requirements is met today.

## 2. Baseline: what the hosted pipeline does today

The current native path is a hosted path, and every one of its assumptions is invalid in a kernel image.

| Component | Current behavior | Why it cannot boot |
|---|---|---|
| `LlvmBackend::write_object` (`codegen/llvm/program.rs`) | Calls `target_wrappers::initialize_x86()`, takes `TargetMachine::get_default_triple()`, and uses host CPU name/features. Sets module triple and data layout only in the release branch before `run_passes`. | The host triple is `x86_64-pc-windows-msvc` or `…-unknown-linux-gnu`. There is no cross-target selection, no static relocation model, and no `kernel` code model. Codegen for a bare-metal target is not reproducible from a different host. |
| `target_wrappers.rs` | Defines `LLVM_Initialize*` shims and `initialize_x86()` because the C API's aggregate initializers are `static inline`. Only X86 is initialized. | AArch64/RISC-V targets cannot be selected at all. The shims themselves live in the compiler, not the output, which is fine — but they constrain which triples are usable. |
| `codegen/llvm/linker.rs` | Invokes `clang`/`link.exe`/`cc` and always links `titrate_native` plus `m`, `pthread`, Winsock, NT API, UCRT/VCRT, and `LLVM-C` (because `titrate_native` embeds inkwell). Uses `/FORCE:MULTIPLE` on Windows to paper over a static/dynamic CRT mismatch. | Every one of those libraries is a hosted dependency. The CRT supplies `_start` and initializes libc; LLVM-C drags in the compiler. The resulting executable requires an operating system to load it. |
| `titrate_native` | Provides `titrate_println`, `titrate_string_concat`, `titrate_free` and 359 registered natives (filesystem, sockets, threads, SQLite, process control, `AtomicInt` handles). | The native runtime is built with `std`. Its allocator, unwinding tables, thread-local storage, and syscall layer are precisely what a kernel must provide instead of consume. |
| `analyzer` | Lexical `VarState` (`Live`, `Moved`, `BorrowedImmutable`, `BorrowedMutable`); `unsafe { }` suspends ownership and borrow checks wholesale. | A borrow lives until its lexical scope ends, not until its last use, so ordinary systems patterns (borrow, use, then mutate) are rejected. Blanket `unsafe` also permits operations that have nothing to do with raw memory. |
| `std` + compiler in the artifact | `std`, CRT, `LLVM-C.lib` are linked into the final executable. | Violates the §1 contract directly, inflates the image, and makes the load address and initial stack layout OS-defined. |

The gap is therefore not one feature but a whole execution environment. The design below replaces each hosted dependency with a Titrate-owned equivalent.

## 3. Target model and triples

### 3.1 Canonical triple

The first supported freestanding target is `x86_64-unknown-none`: architecture `x86_64`, vendor `unknown`, operating system `none`. A fourth component (environment) is permitted by the configuration builder — for example `x86_64-unknown-none-elf` — but the operating-system component must be `none`. Hosted triples such as `x86_64-pc-windows-msvc` and `x86_64-unknown-linux-gnu` are rejected by validation before any LLVM call.

### 3.2 Validation already implemented

`FreestandingConfigBuilder::build` enforces (see §15):

- a 3- or 4-component, hyphen-separated triple with no empty components;
- components limited to ASCII letters, digits, `_`, and `.`;
- an architecture in a short allowlist (`x86_64`, `aarch64`, `riscv32`, `riscv64`, `arm`, `thumbv7em`, `wasm32`, `wasm64`);
- an operating-system component of `none`.

The allowlist is the set the roadmap names or that LLVM commonly ships; extending it is a one-line change when a target wrapper is added. Deeper, target-specific checks (valid CPU, ABI, relocation model) belong in codegen once the wrapper exists, not in this configuration type.

### 3.3 Codegen work (design only)

1. Thread a `target: &str` from the CLI through `compile` and `LlvmBackend` into `write_object`. Default to the host triple so hosted builds are unchanged.
2. Initialize the matching LLVM target through `target_wrappers`: keep `initialize_x86()` and add `initialize_aarch64()`, `initialize_riscv()`, etc. behind the corresponding inkwell target features. Unknown architecture must be a hard error, never a silent fallback to X86.
3. Parse with `Target::from_triple`, then call `create_target_machine` with:
   - the requested triple, **not** `get_default_triple()`;
   - CPU `generic` for `none` targets (host CPU features are meaningless and unsafe for cross builds);
   - `RelocMode::Static` and `CodeModel::Kernel` for `x86_64-unknown-none`;
   - `OptimizationLevel::None`, since optimizations remain an explicit `run_passes` step.
4. Set both module triple and module data layout **unconditionally**, not only in release mode. Target-sensitive lowering must be identical in debug and release.
5. Pass the triple to the linker driver (`--target=<triple>` for clang/lld, `/MACHINE:X64` for `link.exe`) and use `ld.lld`/`lld-link` directly for freestanding links so the host driver cannot inject a CRT.

### 3.4 Cross-compilation artifacts

The build host may be Windows while the target is ELF. The design therefore avoids any dependency on host libraries in the freestanding link: a cross linker (`lld`) and a target-specific linker script are inputs, not host tooling discovered from `PATH`. The same `.tr` source, triple, and script must produce byte-identical images from Windows and Linux hosts.

## 4. `titrate_rt`: the no_std runtime

New crate `titrate_rt` (design only), built for the selected triple with `#![no_std]`, `panic = "abort"`, static relocations, and no dependency on `std` or `titrate_native`.

| Piece | Design |
|---|---|
| Bump allocator | A `GlobalAlloc` implementation over the linker-provided `[__heap_start, __heap_end)` range. A single atomic bump cursor advances on `alloc`; `dealloc` is a no-op because the kernel's lifetime is the image's lifetime. Reject zero-sized and overflowing requests, align to 16 bytes, and return `null` when the range is exhausted. Region allocations in Titrate lower to bumps plus a single rewind at region exit. |
| Panic handler | `#[panic_handler] fn panic(&PanicInfo) -> !` formats a short message to the early serial console, then enters a `hlt` loop with interrupts disabled. No unwinding, no `eh_personality`, no backtrace machinery. |
| Early console | Minimal 16550 UART writer used before drivers exist. One `outb` loop; no allocation, no locks, no `std`. |
| Start stub | See §5. A small assembly file (`start.S`) sets up a stack and calls an `extern "C"` Rust/Titrate entry; a naked Rust function is avoided to stay on stable. |
| Image contract | The runtime, kernel modules, and user `.tr` code link into one static ELF. There is no dynamic loader, no TLS startup, no constructors requiring libc. |

The `lib/tt/sys/` standard-library surface that assumes a hosted OS (`Os.tr`, `Sys.tr`, `Process.tr`) is **not** part of this image. A parallel `lib/tt/kernel/` surface provides the primitives the kernel needs; hosted builds keep the existing modules. Both are pure `.tr`, per the roadmap's pure-stdlib principle.

## 5. Custom `_start` and boot handoff

The default entry symbol is `_start` (validated by the configuration builder). The handoff sequence for `x86_64-unknown-none`:

1. Firmware/loader (QEMU with `-kernel`, or GRUB with multiboot2) places the image at its link address and jumps to `_start` in 64-bit long mode with a defined stack, or to a 32-bit trampoline that switches to long mode first.
2. `start.S` establishes a known stack pointer from the linker symbol `__stack_top`, clears direction flags, zeroes `.bss` if the loader did not, and passes the boot-info pointer in the platform ABI's first argument register.
3. `_start` calls `kmain(boot_info)`, which parses multiboot2 tags for memory maps and framebuffer information, initializes the early console, and never returns.
4. `kmain` falls into the scheduler idle loop; any return from `kmain` is treated as a fatal error and halts.

Boot protocol choice: **multiboot2** first, because QEMU can load the ELF directly and the header is a small, inspectable data structure. Limine is the documented alternative if framebuffer or SMP handoff requirements outgrow multiboot2; switching protocols must not change the `_start` contract or the linker script's section names beyond the header section.

The multiboot2 header is a static Titrate constant placed in a dedicated section (§8.6). Its magic, architecture field, and total length are checked at build time by a test that reads the final ELF.

## 6. Linker script and image layout

Design for `linker/x86_64-none.ld` (new asset, not created by this change):

```
ENTRY(_start)
OUTPUT_FORMAT(elf64-x86-64)
SECTIONS
{
  . = 1M;                         /* conventional kernel load address */
  .multiboot : { KEEP(*(.multiboot)) }
  .text      : { *(.text .text.*) }
  .rodata    : { *(.rodata .rodata.*) }
  .data      : { *(.data .data.*) }
  .bss       : { __bss_start = .; *(.bss .bss.*) *(COMMON); __bss_end = .; }
  . = ALIGN(16);
  __heap_start = .;
  . += 16M;                       /* bump-allocator arena */
  __heap_end = .;
  __stack_top = .;
  /DISCARD/ : { *(.eh_frame) *(.comment) *(.note.*) }
}
```

Invariants:

- the multiboot header is first and page-aligned so a loader can find it by scanning the first 32 KiB;
- `__bss_start`, `__bss_end`, `__heap_start`, `__heap_end`, and `__stack_top` are the only symbols the runtime reads; names are part of the runtime/linker contract;
- `.eh_frame`, `.comment`, and notes are discarded because unwinding metadata and toolchain comments are dead weight in a freestanding image;
- the image must fit the QEMU test's memory budget; a fixed 16 MiB arena is a starting point, not a promise.

Link invocation (design only): `ld.lld -nostdlib -static -T linker/x86_64-none.ld -e _start …`. Critically, **no** `titrate_native`, `libc`, `m`, `pthread`, CRT, or `LLVM-C` appears on this command line.

## 7. Removing compiler, std, CRT, and LLVM-C from the output

Two mechanisms, both required:

1. **Do not link them.** The freestanding link is a separate code path from `linker::link`. It starts from an empty library set and adds only the kernel objects and `titrate_rt`. `LLVM-C` stays a build-time dependency of the `trc` compiler binary; it is never an input to the image link. The hosted path's `-lLLVM-C` and `/FORCE:MULTIPLE` workarounds are confined to the hosted path.
2. **Prove they are absent.** A post-link check runs over the ELF and fails gate G10 if any of the following is found:
   - undefined symbols other than an explicit allowlist (`_start` is defined, not undefined);
   - symbol or section names containing `std::`, `core::panicking`, `__rust`, `_Unwind`, `LLVM`, `__security_cookie`, `__C_specific_handler`, `msvcrt`, `libc`, or `pthread`;
   - a `NEEDED` dynamic entry (the image must be fully static);
   - a `llvm-readobj`/`dumpbin` report showing an unexpected entry point.

The check is a small script driven by a test, not a manual inspection, so it runs in CI on every change to the freestanding path.

## 8. Systems-language primitives (all design only)

Every spelling below is a **proposal** for `AGENTS.md`. None of it is accepted by the current parser or analyzer. The guiding constraint is to extend existing module-call syntax where possible rather than add keywords.

### 8.1 Volatile load/store

Proposed module calls, requiring `unsafe` because the compiler cannot reason about address validity:

```titrate
unsafe {
    let flag: u32 = Volatile.load32(addr);
    Volatile.store32(addr, 1);
}
```

LLVM lowering is `load volatile` / `store volatile` with the target's natural alignment; no reordering across the operation by LLVM or by the Titrate optimizer. Widths: 8, 16, 32, 64 bits. Volatile operations must not be folded, merged, or eliminated by `run_passes`.

### 8.2 Inline asm

Proposed expression form, restricted to `unsafe`:

```titrate
unsafe {
    let out: u64 = asm!("rdtsc", outputs = ["=a", "=d"]);
    asm!("hlt");
}
```

Lowering uses LLVM's `call asm` with explicit constraints, clobbers, and `sideeffect`/`nounwind` flags. Rules: the template must be a string literal at compile time; operands are typed; inputs and outputs are counted and checked against the constraint list; no branch to a label defined outside the block. A stripped-down Titrate IR node (`Asm`) is needed so all three backends can either lower it or reject it with a diagnostic — the VM cannot execute host instructions and must refuse, not silently no-op.

### 8.3 MMIO

MMIO is volatile access at a fixed address. Proposal: the same `Volatile` module plus a marked-address helper so the intended semantics are visible in source:

```titrate
let status: u32 = Volatile.read32(Mmio.address(0xF000_0000));
```

Design requirement: MMIO and ordinary loads must not be CSE'd or reordered. The analyzer tags such addresses as volatile-derived; the optimizer treats any load/store through them as a barrier for surrounding memory operations.

### 8.4 Port I/O

x86-only, `unsafe`, lowered to LLVM x86 `in`/`out` intrinsics:

```titrate
unsafe {
    IoPort.out8(0x3F8, 0x41);      // serial transmit
    let byte: u8 = IoPort.in8(0x3F8);
}
```

Port numbers are compile-time constants in the first iteration; a dynamic port requires an explicit range check because the instruction encodes an immediate or `DX`. Other architectures reject these calls at compile time with a target-specific diagnostic.

### 8.5 Atomics with explicit orderings

Today's `AtomicInt_*` natives are SeqCst-only and handle-based, which is correct for hosted scripts but not for kernels. Proposal: a value-based `Atomic<T>` primitive plus a `MemoryOrdering` enum:

```titrate
enum MemoryOrdering { Relaxed, Acquire, Release, AcqRel, SeqCst }

let old: int = counter.fetchAdd(1, MemoryOrdering.AcqRel);
if (flag.compareExchange(expected, desired, MemoryOrdering.Acquire, MemoryOrdering.Relaxed)) { ... }
fence(MemoryOrdering.SeqCst);
```

Lowering is LLVM atomic `load`/`store`/`rmw`/`fence` with mapped orderings and the target's required alignment. Constraints:

- invalid ordering/instruction combinations (`Acquire` on a store, `Release` on a load, `AcqRel` on a load) are compile errors;
- size must be 1, 2, 4, or 8 bytes; larger atomics use a libcall that the freestanding runtime must provide or the compiler rejects;
- the VM path either models the ordering faithfully or rejects the operation — no weak approximation;
- hosted `AtomicInt_*` natives remain unchanged for source compatibility.

### 8.6 Layout control

Proposed attributes (new syntax, design only):

```titrate
#[repr(C)]
struct MultibootTag { totalSize: u32, tagType: u32 }

#[repr(packed)]
#[section(".multiboot")]
const MB_HEADER: MultibootTag = ...;

#[union]
union Word { bits: u64, halves: (u32, u32) }
```

Requirements: explicit field offsets and sizes, predictable padding, `repr(C)` for all structures crossing the Titrate/ABI boundary, packed layout only for hardware registers and boot headers, unions readable only where `unsafe` is permitted, and section placement verified by the post-link ELF check. Struct layout must be computed identically in the analyzer, LLVM backend, and bytecode VM so cross-backend parity is not broken for programs that use layout attributes.

## 9. Real NLL borrow checking and drop flags

### 9.1 Current limitation

`analyzer::scope::VarState` is a four-value lexical state stored per variable. A borrow created by `&x` remains `BorrowedImmutable`/`BorrowedMutable` until the enclosing scope ends. This rejects safe code such as:

```titrate
let r = &x;
print(r);
x = new_value;   // rejected today although r's last use was the previous line
```

### 9.2 Non-lexical lifetimes (design only)

Replace the lexical map with loans over a control-flow graph:

- Build a CFG per function from the typed AST; assign a program point to each statement and expression.
- A borrow creates a loan with a region: the set of points where the resulting reference may be used, computed by liveness of the reference variable and propagated backwards through successors.
- A loan is killed at its last use, not at scope exit. Mutable access is allowed once no live loan overlaps the write.
- Handle loops with a fixed point over back edges; handle `break`, `continue`, `return`, `throw`, and `?` as CFG exits with their own liveness sets.
- Add two-phase borrows for method-call receivers so `list.push(list.len())` is accepted.
- Keep the existing diagnostics and error codes (`E0XXX`) so hosted source compatibility is preserved; NLL only removes false rejections.

The migration is analyzer-local and must not weaken any current rejection: every program accepted by the lexical checker must remain accepted, and every program it rejects must either stay rejected or be accepted only with a proven non-overlapping loan region. A differential test corpus enforces that.

### 9.3 Drop flags on all exits (design only)

The analyzer must insert cleanup deterministically for every value with a destructor, on every exit:

- one drop flag per droppable binding, initialized to "not live" at declaration and set when the value is fully initialized;
- a move or partial move clears the relevant flag(s), including per-field flags for structs and tuples;
- at each exit — end of scope, `return`, `break`, `continue`, `throw`, an error propagated by `?`, and a `switch` arm that leaves the scope — emit a conditional drop for every flag still set;
- loops reset flags on each iteration so a conditionally initialized binding cannot be dropped twice;
- with `panic = "abort"` there is no unwind path to clean up, but all normal exits above still need flags. If unwinding is ever reintroduced, landing pads become a new required exit class.

Drop flags are a codegen concern shared by all three backends; the VM must track the same liveness to keep byte-identical observable output.

### 9.4 Scoped `unsafe` (design only)

`unsafe { }` currently suspends all ownership and borrow checks. In a systems language it must be narrow: an `unsafe` block permits only an enumerated set of operations — raw pointer creation/dereference, volatile/MMIO access, port I/O, inline asm, union field access, and calls to explicitly unsafe extern functions. Move, borrow, and drop checking stay on inside `unsafe`. Each permitted operation gets its own diagnostic when used outside the block. This change is source-compatible only if code relying on the blanket suspension is migrated; the roadmap's `--compat` switch is the vehicle for that migration.

## 10. Kernel substrate (all design only)

Delivered as `lib/tt/kernel/` modules plus a thin `titrate_rt` layer, in dependency order:

1. **Early boot:** GDT with flat segments, stack setup, `.bss` clear, multiboot2 tag parsing.
2. **Interrupts:** IDT with 256 entries, ISR/IRQ stubs, PIC remapping to vectors `0x20`–`0x2F` (with IOAPIC as the SMP follow-up), a generic handler that dispatches to registered Titrate handlers. Page faults and general-protection faults print a register dump and halt.
3. **Timing:** PIT/HPET or TSC deadline for a periodic tick that drives preemption.
4. **Physical memory:** bitmap allocator built from the multiboot memory map; regions marked reclaimable are the only ones handed out.
5. **Virtual memory:** 4-level paging, kernel mapped at the higher half (`0xFFFFFFFF80000000` on x86_64), map guards and page-level permissions, `INVLPG` on unmap, a debug check that user mappings never carry the supervisor bit.
6. **Heap:** the bump allocator from §4 for early boot, replaced by a page-backed allocator once paging is live.
7. **Concurrency:** spinlocks with interrupt disabling, `Mutex`/`Condvar` equivalents built on the §8.5 atomics, per-CPU state, and a bounded number of kernel threads.
8. **Scheduler:** cooperative round-robin first, then preemptive tick-driven switching with per-thread kernel stacks; no user processes are required for gate G10.
9. **Drivers:** serial console, VGA text or multiboot framebuffer, PS/2 keyboard, PCI enumeration, and a virtio-blk or ramdisk block device for QEMU.
10. **Syscall entry:** `syscall`/`sysret` with a fixed, versioned syscall table, explicit pointer validation at the user/kernel boundary, and capability checks inherited from the VM's trusted/untrusted model.

The syscall table and the multiboot header are trust boundaries: every field from the loader or user mode is validated before use, and no unchecked pointer from either source is dereferenced.

## 11. Boot path, step by step

1. Build: compile `.tr` + `titrate_rt` to objects for `x86_64-unknown-none`; link with `ld.lld` and the linker script; run the ELF purity check.
2. Launch: `qemu-system-x86_64 -kernel kernel.elf -serial stdio -m 256M` (or GRUB for the multiboot2 path).
3. Loader: validates the multiboot2 header, loads the ELF at 1 MiB, jumps to `_start`.
4. `start.S`: sets `__stack_top`, clears flags, passes boot info, calls `kmain`.
5. `kmain`: early console, memory map parse, GDT/IDT, paging, heap, scheduler, drivers.
6. Success signal: a fixed banner on serial (for example `TITRATE-OK`) plus a responsive keyboard/console loop. QEMU test waits for the banner with a timeout and fails otherwise.
7. Failure paths: triple fault or panic handler output is captured and reported as a test failure with the serial log attached.

## 14. Risks and mitigations

| Risk | Mitigation |
|---|---|
| LLVM `none` targets need target features the current inkwell build lacks | Extend inkwell features and `target_wrappers` one target at a time; fail loudly for unsupported triples |
| LLVM reorders MMIO or volatile operations during `run_passes` | Emit `volatile` IR and test the optimized IR for preserved order; add barriers around MMIO-derived addresses |
| NLL weakens an existing rejection | Differential corpus against the lexical checker; every accepted new case needs a last-use proof in its test |
| Drop flags diverge between backends | One analyzer-computed liveness model consumed by LLVM, bytecode, and WASM; parity test includes destructors and `?` exits |
| Boot works only on one loader | Keep the `_start` and linker-symbol contract protocol-independent; test both QEMU `-kernel` and multiboot2/GRUB |
| Hosted link regresses because `LLVM-C`/CRT handling is shared | Freestanding uses a separate link function; hosted `linker.rs` is untouched, and the full hosted suite must stay green |
| Image purity check produces false positives | Keep an explicit, reviewed allowlist; assert both directions (required symbols present, forbidden names absent) |

## 15. Implemented scaffolding reference

`trc/src/codegen/llvm/freestanding.rs` is the only executable artifact of this change. It provides:

- `FreestandingConfig` — immutable, validated configuration with accessors for target triple, entry symbol, linker script path, and panic strategy.
- `FreestandingConfigBuilder` — incremental builder with `new`/`Default`, setters for all four fields, and `build() -> Result<FreestandingConfig, ConfigError>`. Defaults: entry symbol `_start`, panic strategy `Abort`; target triple and linker script are required.
- `PanicStrategy` (`Abort`, `Unwind`) with `as_str()` and `Display`; `Unwind` is accepted as input so validation can reject it with a precise diagnostic instead of a parse error. `Abort` is the only strategy a freestanding image can use.
- `ConfigError` — carries the offending field name and a message, implements `Display` and `std::error::Error`.
- Unit tests covering defaults, a valid minimal build, each missing field, malformed triples (wrong component count, empty component, unknown architecture, hosted OS), invalid entry symbols, invalid linker script paths, and the rejected `Unwind` strategy.

`trc/src/codegen/llvm/mod.rs` gains exactly one line: `pub mod freestanding;`. No other file is changed by this work, and no hosted function is called from the new module.
